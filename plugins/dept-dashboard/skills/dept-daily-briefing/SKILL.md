# DEPT 일일 브리핑

1. 먼저 `data_catalog`(있으면 요청에서 지정한 주제로 좁힘, 없으면 `get_dashboard_guide`)를 읽고 확인할 지표·비교 기준을 한 줄로 알린다. 데이터 기준은 KST. "오늘"은 브리핑을 받는 시점을 뜻하며 기본은 마지막 **완료된** 날짜와 직전 비교 기준이다. 오늘 수치를 명시적으로 요청하면 사용 가능한 오늘 집계만 별도 표시하고 미완료 숫자를 완결된 어제와 직접 비교하지 않는다.
2. 가능하면 `analyze_overview`를 먼저 사용한다. 완료일과 직전 하루 비교가 가능하면 기준 날짜·비교 인자를 명시한다. 주제가 광고나 특정 곡으로 한정됐으면 카탈로그의 해당 분석 도구를 쓴다. 지표별 실제 기준일과 수집 상태를 확인하고, `dept-dashboard-data` 3절의 기간 규칙을 적용한다. 기본 분석이 최근 7일 비교라면 7일 신호로 표시하고 당일 급변으로 바꿔 말하지 않는다. 분석 도구가 없으면 `get_alerts`와 카탈로그에 있는 관련 지표에 범위를 좁힌다. 빈 알림 목록을 전체 지표 정상으로 해석하지 않는다.
3. 도구가 표시한 이상 또는 실제로 비교 가능한 값으로 확인한 큰 변화만 고른다. 같은 이슈는 하나로 합치고, 업무 영향·근거의 선명도 순으로 최대 3개. 각 줄에 **무엇이 달라졌는지 → 근거 숫자와 실제 기준일(링크가 있으면 첨부) → 다음에 확인할 한 가지**를 쓴다. 가설은 사실처럼 단정하지 않는다.
4. 확인한 범위에서 이상이 없고 요청 범위(별도 지정이 없으면 카탈로그에서 이번에 확인하기로 한 주요 지표)가 정상적으로 수집됐으면 `특이사항 없음 · <확인 범위와 기준일>` 한 줄만 쓴다. 수집 지연·조회 실패·미확인 범위가 있으면 별도 `판단 보류: …`로 명시한다. 일부만 확인했다면 범위를 밝힌 `확인한 범위 내 특이사항 없음`을 사용한다. 확인된 것이 전혀 없으면 `판단 보류`만 쓰며 특이사항이 없다고 하지 않는다.
