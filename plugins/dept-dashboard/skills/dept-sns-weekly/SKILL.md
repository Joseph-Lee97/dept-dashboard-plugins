# SNS 주간 요약

> **먼저 보고 일하기:** `data_catalog`가 있으면 먼저 불러(해당 recipe·데이터셋 cautions·도구 인자 확인) 쓸 데이터·도구와 이유를 한두 줄로 말한 뒤 조회한다. 숫자에는 `evidence`의 as_of·대시보드 링크를 각주로 붙인다. 자세한 규칙은 `dept-dashboard-data` 0·6절.

## 기간
- 말이 없으면 최근 7일(끝 = 어제) vs 직전 7일. `dept-dashboard-data` 3절의 비교 조건을 적용한다. `days`는 조회 범위를 잡는 인자이지 요청한 보고 기간을 보장하지 않는다. 게시일을 KST로 변환해 요청 구간으로 자르고, 도구 범위가 그 기간을 덮지 못하면 해당 게시물 섹션은 일부 또는 조회 불가로 표시한다.

## 데이터 모으기
1. 계정 지표: `analyze_overview`가 있으면 그 결과의 `sns.accounts`(계정별 value·change·prev_change)와 `sns.drops`(줄어든 계정)를 쓴다.
   없으면 `get_sns_metrics` {from:<직전 시작>, to, granularity:"day", metric:"followers"} — 계정(platform+channel_label)마다 기간 끝 값 − 기간 시작 직전 값. 유튜브는 metric "subscribers", QQ뮤직은 "fans", 비스테이지는 "members".
2. 게시물: `get_sns_post_performance` {days:7, sort:"views", limit:10} — 누적 조회 기준 후보와 `milestones`의 d1/d3/d7. 직전 주까지 볼 때는 `days:14` 등 도구가 허용하는 범위로 조회한 뒤 `posted_at`으로 나눈다. 상위 N개를 뽑은 한 응답을 기간별로 나눴다고 해서 각 주의 전체 또는 각 주 Top N이라고 부르지 않는다.
   - **성과 비교:** 같은 D+시점(기본 D+1, 요청 시 D+3/D+7)에서 값이 있는 후보끼리 내림차순으로 정렬한다. 기록이 없거나 해당 시점에 도달하지 않은 게시물은 순위에서 제외하고 0으로 보지 않는다. 누적 조회로 뽑은 표본이면 `확인한 후보 중`으로 표시한다. 누적 조회 순위는 따로 요청했거나 동일 시점으로 비교할 수 없을 때만 `누적 조회 참고`로 제공한다.
   - **전체 게시물 수:** 기간·플랫폼/계정 필터가 정확히 일치하는 집계 총계 또는 해당 기간의 완전한 조회가 확인된 경우에만 센다. `limit`·순위·잘림·일부 조회의 반환 행 수는 게시물 총계가 아니다. 전체 건수를 확인하지 못한 기간은 `전체 집계 미확인`으로, 두 기간 모두 확인된 경우에만 증감을 표시한다.
3. 플랫폼만 보고 싶으면 platform(instagram, tiktok, youtube, xiaohongshu, bilibili, douyin, weibo 등)이나 account로 좁힌다.

## 답 형식
```
SNS 주간 요약 · 기간 vs 직전

한 줄 결론: <가장 많이 는 계정 + 가장 잘 된 게시물>

| 계정 | 팔로워(구독자) | 이번 주 증감 | 직전 주 증감 |
(주요 계정 위주, 협력자 계정은 변화 있을 때만, 줄어든 곳은 표시)

잘 된 게시물 최대 3개(동일 D+시점, 표본이면 "확인한 후보 중")
| 플랫폼 | 올린 날 | 제목(짧게) | D+1 조회 |

전체 게시물 수: N개(직전 N개) / 확인 못 한 기간은 "전체 집계 미확인"

짚을 점 2~3개(예: 팔로워 급증 계정과 같은 주 게시물, 줄어든 계정)
기준: <도구> · 기간 · 마지막 수집일
```

## 지킬 것
- 누적 조회는 비교한 D+시점 값과 섞지 않는다. 같은 시점의 값이 없으면 성과 우열을 판단하지 않는다.
- 팔로워 같은 누적값은 날짜끼리 더하지 않고 끝 값 − 시작 값.
- 계정 아이디·연락처 외 개인정보는 없다. 정산 금액도 이 연결에 없다.
